# 개발 계획 — 현장별 공정·기성 대시보드

## 한눈에 보기

1. EPIC 3개, Story 13개로 만듭니다(실습조건: EPIC 3개 이하, Story 15개 미만).
2. 순서는 ① 자료 가져오기·필터·현황·추이 → ② 점검 현장·기록 펼침·CSV → ③ 근거를 보여 주는 AI 질의입니다.
3. 마지막에 정답 숫자 표를 화면에서 하나씩 확인하는 Story(3-4)로 로컬 전체 검증을 마치고, 결과를 보고한 뒤 멈춥니다.
4. GitHub 저장과 Vercel 배포는 EPIC·Story에 넣지 않았습니다. 사용자가 각각 따로 요청한 뒤에만 진행합니다.
5. Story는 사용자가 확인했다고 답하기 전에는 "확인 대기"이며 완료로 표시하지 않습니다.

## 진행 방식

- 이번 진행에서는 사용자의 요청에 따라 EPIC 1~3을 이어서 만들고, EPIC마다 자동 검사를 돌렸습니다. 작업규칙의 기본은 EPIC 하나씩이지만 이번만 한 번에 만들었습니다.
- 확인 행동은 모두 브라우저(`http://localhost:3000`)에서 하는 것입니다. 터미널·개발자 도구를 보지 않아도 됩니다.
- 자동 검사: `npm test`(Vitest), `npx tsc --noEmit`, `npm run lint`, `npm run build`와 브라우저 자동 조작. 결과는 `05_테스트결과.md`에 적습니다.
