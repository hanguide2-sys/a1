# FRD — 현장별 공정·기성 대시보드

## 한눈에 보기

1. 사용자가 누르거나 고르는 것 17가지를 "무엇을 하면 → 프로그램이 무엇을 하고 → 화면에 무엇이 보이는지"로 정리했습니다.
2. 월·지역·유형·현장 필터는 현황·추이·비교표·CSV·AI에 똑같이 적용됩니다.
3. 누적기성액은 월말까지 쌓인 금액이고, 당월기성액은 전월 누적과의 차이입니다. 첫 달은 "계산 불가"입니다.
4. 비교표의 행을 펼치면 선택 월의 공사기간·기록된 상황·기록된 대응 계획이 나옵니다.
5. 오류가 나도 지금 자료는 유지되고, AI가 실패해도 대시보드와 CSV는 계속 씁니다.

- 이 문서는 `01_PRD.md`의 결정(질문 7개의 답)을 바꾸지 않습니다.
- `design` 폴더에 시안이 아직 없어 화면 배치는 PRD "화면 요약"을 기준으로 했습니다. 배치만 `(AI 결정)`이며, 시안이 들어오면 배치만 맞추고 기능은 바꾸지 않습니다.
- GitHub 저장·Vercel 배포는 이 앱의 기능이 아닙니다. 사용자가 별도로 요청한 뒤에만 진행합니다.

## 4. 계산 규칙 표

예시는 `data/검산표.md`의 숫자입니다. 금액은 백만원, 비율은 %, 공정차이는 pp입니다.

### 4-1. 현장 한 곳의 값

| 항목 | 계산 방법 | 예시 (검산표 숫자) |
|---|---|---|
| 현장 기성률 | 누적기성액 ÷ 계약금액 × 100 | D 9월: 50,384.4 ÷ 72,600 × 100 = 69.4% |
| 현장 공정차이 | 실제 공정률 − 계획 공정률 | D 9월: 75.8 − 86.5 = −10.7pp |
| 상태 | 0pp 이상 정상. −5pp 초과 0pp 미만 주의. −5pp 이하 점검. 소수 오차 때문에 −5.0이 −4.9999처럼 계산되지 않게 판정합니다(AI 결정). | 계획 70·실제 70 → 정상. 계획 70·실제 65.1 → 주의. 계획 70·실제 65 → 점검 |
| 점검 순위 | 상태가 점검인 현장만, 공정차이가 작은 순. 같으면 현장 ID 순 | 9월: D(−10.7) → I(−7.6) → K(−5.4) |
| 상태 개수 | 범위 안 현장을 상태별로 셉니다. | 9월 전체: 정상 6 · 주의 3 · 점검 3. 경기: 정상 2 · 주의 1 · 점검 1 |

### 4-2. 여러 현장(범위)의 값 — 선택한 한 달만

| 항목 | 계산 방법 | 예시 (검산표 숫자) |
|---|---|---|
| 전체 기성률 | 범위 현장의 누적기성액 합계 ÷ 같은 현장의 계약금액 합계 × 100 | 9월: 424,063.4 ÷ 630,700 × 100 = 67.2% |
| 전체 계획·실제 공정률 | 현장 계약금액으로 가중평균. Σ(계약금액 × 공정률) ÷ Σ계약금액 | 9월: 계획 73.2% · 실제 71.2% |
| 전체 공정차이 | 반올림하기 전의 가중 실제 − 가중 계획. 화면에 반올림해 보이는 두 값을 다시 빼지 않습니다. | 9월: −2.0pp |
| 표시 반올림 | 계산 중에는 반올림하지 않고, 마지막에 %·pp·금액을 소수 첫째 자리로 반올림합니다. | 424,063.4 / 67.2% / −2.0pp |
| 자료 없음·분모 없음 | "자료 없음" 또는 "계산 불가"로 보여 줍니다. 0%로 대신하지 않습니다. | 현장이 없는 범위(인천·물류시설)의 기성률 → 계산 불가 |
| 여러 달 합산 금지 | 월별 계약금액·누적기성액을 여러 달 더해 전 기간 총액으로 보여 주지 않습니다. | 7·8·9월 누적기성액(364,718.5 / 395,184.7 / 424,063.4)을 더하지 않습니다. |

### 4-3. 누적 값과 당월기성액의 구별

| 항목 | 계산 방법 | 예시 (검산표 숫자) |
|---|---|---|
| 누적기성액 | 자료의 월말 누적기성액. 그 달까지 쌓인 금액입니다. 청구액·수금액·미수금이 아닙니다. | D 9월: 50,384.4 |
| 당월기성액(현장) | 같은 현장의 당월 누적기성액 − 바로 전월 누적기성액 | D 9월: 50,384.4 − 47,044.8 = 3,339.6 |
| 첫 달·전월 없음 | 계산 불가(null). 0으로 바꾸지 않고, 누적액을 당월액으로 대신하지 않습니다. | 2025-10: 계산 불가. 누적 105,449.7은 10월 기성이 아닙니다. |
| 당월기성액이 0.0 | 정상값입니다. 누락과 구별해 "0.0"으로 표시합니다. | J 7월: 26,308.8 − 26,308.8 = 0.0. 기록은 "기성 확인 서류 보완" |
| 전체 당월기성액 | 범위의 모든 현장에 당월·전월 값이 있을 때 현장별 차액을 합산합니다. 하나라도 없으면 계산 불가입니다. | 9월 전체: 424,063.4 − 395,184.7 = 28,878.7 |
| 기성률과 공정률의 차이 | 기성률은 금액 기준, 공정률은 공정 기준입니다. 같을 필요가 없고 서로 대신하지 않습니다. | D 9월: 실제 공정률 75.8%, 기성률 69.4% |
| 기성 증가와 공정 | 당월기성액이 늘었다는 것이 공정이 급증했다는 뜻은 아닙니다. | J 8월 당월기성액 2,332.8(28,641.6 − 26,308.8). 기록: 7월 확인분 반영 |

### 4-7. 가져오기 검사 규칙

| 항목 | 검사 방법 | 예시 |
|---|---|---|
| 필수값 | 15개 열이 모두 있어야 하고 비어 있으면 안 됩니다. 빈칸을 0으로 바꾸지 않습니다. | `오류_공정률빈값.csv` 134행 A의 actualProgress 빈칸 → 거부 |

| JSON 정보 | JSON은 schemaVersion 2.0, 금액·공정률 단위, 필수 필드 목록을 확인합니다. CSV는 단위 정보가 없다고 안내합니다. | schemaVersion이 다르면 거부 |
| 월 누락 | 오류가 아니라 경고입니다. 확인 가능한 행만 집계하고, 전월 누락 시 당월기성액은 계산 불가입니다. | 특정 현장의 2026-03 행이 없으면 경고 + 그 달·다음 달 당월기성액 계산 불가 |
| 교체 | 검사와 미리보기를 거친 뒤에만 전체를 교체합니다. 오류·취소 시 지금 자료를 유지합니다. | CSV 144행 → JSON 144행(288행 아님) |

### 4-8. AI에게 보내는 자료

| 항목 | 방법 | 예시 (검산표 숫자) |
|---|---|---|
| 항상 보내는 것 | 지금 범위의 선택 월 원문 행과 프로그램이 계산한 지표(기성률·공정차이·상태·당월기성액), 선택 월까지 월별 요약. 원문과 계산 결과는 구분합니다. | 9월 전체: 12개 현장 행 + 계산 지표 + 12개 월 요약 |
| 현장 1곳 선택 | 그 현장의 시작 월~선택 월 원문 기록도 보냅니다. | J 선택 후 "7월 기성이 왜 늘지 않았나?" → 7월 기록(기성 확인 서류 보완)으로 설명 |
| 보내지 않는 것 | 범위 밖의 현장·월, API 키 | 범위 밖 질문 → "전달한 자료 범위 밖입니다" |
| 답변 근거 | 기준 월·현장 ID·참고 필드 또는 월별 요약을 함께 보여 줍니다. | 9월 전체 "점검 현장은?" → 2026-09 / D, I, K |
| 설명 방식 | issueSummary는 "기록된 상황", actionPlan은 "기록된 대응 계획"으로 설명합니다. contractEndDate는 "계약상 준공일"로만 설명합니다. | D "늦어진 원인과 대응은?" → 공급 정상화 후에도 남은 지연과 주간 확인 계획을 기록대로 설명 |
| 자료 없음 안내 | 실제 준공일·미수금·수금·기상 실측은 자료가 없다고 답합니다. | "실제 준공일·미수금은?" → 자료 없음, 계약상 준공일과 실제 완료일은 다름 |
